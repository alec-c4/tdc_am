# План редизайна tdc.am

Статус: **реализовано** (первая версия). Дизайн-направление — концепт **«Ararat»**.

Собрано на Astro + Svelte: 34 статические страницы (hy/en/ru × главная, о компании,
список услуг, 6 карточек услуг, партнёры, контакты + 404), `astro build` проходит без
ошибок. Осталось по плану: реальная отправка формы, хостинг, вычитка EN/RU носителем —
см. открытые пункты в разделе 6.

## 1. Дизайн-система (утверждено)

- **Палитра:** basalt `#211d1a` (тёмный, вулканический камень), stone `#f2ebe0` (тёплый светлый фон, розовый туф Еревана), apricot `#e07830` / apricot-deep `#a6531f` (акцент — армянский абрикос), ink-soft `#6b5f52`. Светлая и тёмная тема — обе определены токенами.
- **Типографика:** Bricolage Grotesque (заголовки, характерный «резной» рисунок), Hanken Grotesk (основной текст), IBM Plex Mono (цифры статистики, лейблы, нумерация услуг).
  - ⚠️ **Риск:** ни Bricolage Grotesque, ни Hanken Grotesk не поддерживают армянскую графику. Для `hy`-версии нужен запасной вариант — предлагаю **Noto Sans / Noto Serif Armenian** как системную пару для армянского текста (латиница/кириллица остаются на Bricolage/Hanken), либо самостоятельно закупленный армянский бренд-шрифт (например, Mardoto/GHEA), если он есть у клиента. Нужно решение — см. раздел 6.
- **Мотив:** силуэт двуглавой горы (Арарат) как декоративный SVG-элемент в hero и разделителях секций.
- **Ключевые паттерны вёрстки:** асимметричная офсетная сетка карточек услуг, крупная уверенная типографика в hero, статистика — крупными цифрами построчно, команда — с цветной верхней линией вместо рамки карточки.

Референс: опубликованный макет главной страницы (концепт 2 «Ararat») — https://claude.ai/code/artifact/b91ba2d8-0e8a-4f7b-91ff-6728b1404b7b

## 2. Технологический стек

- **Astro** (уже используется в репозитории, `astro@^7.3.2`) — статическая генерация (SSG) для всех языковых версий.
- **Svelte** — только для интерактивных островков:
  - переключатель языка (сохраняет текущую страницу, меняет только локаль в URL);
  - мобильное меню (гамбургер);
  - форма обратной связи (валидация + отправка + статус);
  - анимация чисел в блоке статистики при появлении в вьюпорте (уважает `prefers-reduced-motion`).
  - Всё остальное — обычные `.astro`-компоненты, без лишнего JS.
- **i18n:** встроенный роутинг Astro (`i18n` в `astro.config.mjs`), локали `hy` (по умолчанию), `en`, `ru`. Тексты — в JSON-словарях или Content Collections по языкам; данные услуг/команды/партнёров — в Content Collections (по одной записи на услугу/сотрудника/партнёра), чтобы контент редактировался без правки шаблонов.
- **SEO:** `@astrojs/sitemap`, `robots.txt`, `<link rel="canonical">` + `hreflang` на все языковые альтернативы, Open Graph/Twitter meta, JSON-LD `ProfessionalService`/`AccountingService` со адресом и телефоном, оптимизация изображений через `astro:assets`, семантические заголовки, alt-тексты.
- **Доступность:** видимый фокус, контраст текста на акцентных фонах, поддержка `prefers-reduced-motion`, управление с клавиатуры.

2. Моделирование контента (Content Collections: услуги, команда, партнёры, словари переводов).
3. Общий каркас: Layout, Header/Footer, переключатель языка, мобильное меню.

5. Внутренние страницы: О компании, Услуги (+ 6 страниц услуг), Партнёры, Контакты (+ форма).
6. SEO-пакет: sitemap, robots.txt, meta, JSON-LD, hreflang, OG-изображения.
7. Доступность и производительность (Lighthouse, контраст, `prefers-reduced-motion`).
8. Проверка контента с клиентом (арм. текст — сверен с оригиналом; рус./англ. — черновой перевод, нужна вычитка).
9. QA на устройствах и браузерах → стейджинг → финальное согласование → релиз.

## 6. Решения по открытым вопросам

1. **Хостинг/деплой** — пока не выбран. Собираем чистый статический сайт (`astro build` → `dist/`), без завязки на конкретный адаптер; адаптер/платформу подключаем отдельным шагом, когда решение будет.
2. **Форма обратной связи** — вёрстаем и делаем клиентскую валидацию (Svelte-компонент) сейчас; реальную отправку (серверлесс-функция/SMTP/сторонний сервис) подключаем позже отдельной задачей. До интеграции форма при сабмите показывает понятное состояние «отправка временно недоступна» вместо тихого провала.
3. **Шрифт для армянского текста** — используем Noto Sans/Serif Armenian как запасной вариант для `hy`-локали (решение по умолчанию, т.к. у клиента нет готового корпоративного армянского шрифта).
4. **Логотип** — оставляем текущий знак («комета» + `tdc`), перерисован как чистый SVG: `public/logo-mark.svg` (уже сделан и сверен визуально с оригиналом `tdc.am/images/logo.png`).
5. **Переводы EN/RU** — черновой перевод с армянского готовлю я; нужна вычитка клиентом/носителем перед публикацией (переключатель языка на живом сайте сейчас не работает, готового текста нет).
6. **URL-стратегия локалей** — армянский без префикса (`/`, `/en/`, `/ru/`), как на текущем сайте — не теряем позиции `/` в поиске.
7. **Страницы услуг** — 6 отдельных страниц (`/services/<slug>/`) вместо одной страницы с якорями.
